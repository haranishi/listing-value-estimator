# PriceScopeの現状仕様と構成

2026-10-30。既存READMEの静的Webアプリの範囲を引き継ぎ、現在の計算とデータ境界を記録する。

## 要件と対象外
- 利用者が商品の属性と売却条件を入力し、4種類の目安価格、売れやすさ、理由、改善項目、出品文を得られる。
- 実売データ取得、画像査定、JAN/型番スキャン、価格の自動変更、外部サービスへの出品は未実装。
- 「相場」「確度」は固定係数から計算した表示で、実売記録による査定や販売成立確率の測定ではない。

## 構成
| 役割 | 実装の正本 |
| --- | --- |
| 商品・条件のフォーム、結果、コピー操作 | [index.html](../index.html) |
| 係数、計算、説明文、描画、コピー | [app.js](../app.js) |
| 表示 | [styles.css](../styles.css) |

`input`と`change`が`render`を呼び、`getFormData → calculate → 各描画関数`で結果を更新する。コピー時も現在のフォームから計算する。

## 入力と計算
- `getFormData`は商品名、カテゴリ、ブランド、購入価格、経過年数、状態、付属品、需要、希少性、売却速度、季節性、信頼項目、補足を読む。
- 基準率は`categoryRules`の基準値×`max(0,1-年数×年間減価率)`を、そのカテゴリの下限/上限へ収めた値。
- `market`は購入価格×基準率×6属性の係数×選択した信頼項目の価格係数を`roundPrice`で丸める。
- `quick/recommended/premium`は`market`と`speedRules`から計算する。表示レンジは`market`の0.82〜1.18倍を丸めた値。
- `roundPrice`は3000円未満を100円刻み・最低300円、30000円未満を500円刻み、それ以上を1000円刻みにする。
- 売れやすさは属性補正・信頼項目・年数から計算して18〜96、確度は入力の充実度等から35〜94に制限する。
- 商品名や補足は説明文へ反映する。実売相場や外部AIを問い合わせて値を補正する処理はない。

## データ境界
- 状態は現在のDOM入力だけにあり、`localStorage`・cookie・サーバーへの保存や同期は実装されていない。
- 「コピー」で価格の要約と出品文をクリップボードへ渡す。外部の出品サービスへ送信・公開する操作ではない。
- HTTPS等のsecure contextでClipboard APIを使えれば`writeText`、それ以外は一時textareaと`execCommand('copy')`を使う。
- 入力画面の数値制約はHTMLにあり、計算関数は画面の既定カテゴリ/選択値を前提とする。任意JSONを受け付けるAPIはない。

## 変更時の検証条件
- 合成の商品属性で同じ入力が同じ結果を返し、カテゴリ・状態・需要・信頼項目等の変更が結果と理由に反映されること。
- 3000/30000円の前後、購入価格0、経過年数の上限と下限、係数の下限/上限を確認する。
- 売れやすさ18〜96、確度35〜94、表示レンジと4価格が実装の式と丸め規則に合うこと。
- 商品名や補足にHTML記号を含め、画面表示と出品文が入力を実行可能なHTMLとして扱わないことを確認する。
- secure contextのコピー、fallback、拒否時の表示を分けて確認する。再読込後に入力履歴が保存されないことを確認する。
- 現在、リポジトリに自動テストやpackage manifestはない。上記は次の変更で満たす確認条件であり、今回の動作試験結果ではない。

## 今回の記録
- 根拠は`app.js`の`getFormData`、`calculate`、`roundPrice`、`renderCopy`、`copySummary`とフォームイベント。
- 計算係数・画面・サンプル・依存を変更せず、現状設計の入口だけを追加した。
